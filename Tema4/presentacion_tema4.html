Fase Inicial del Compilador: El Analizador Léxico

La tokenización transforma un flujo continuo de caracteres en componentes léxicos estructurados.

1. Entrada del Lexer

Recibe una secuencia de caracteres pura (código fuente / string) exactamente como fue escrita por el programador.

int contador = 10;
// Inicio del bucle
2. Proceso de Tokenización

Escanea carácter por carácter, elimina comentarios e ignora espacios, tabulaciones y saltos de línea no semánticos.

3. Salida hacia el Parser

Emite una secuencia ordenada de tuplas o Tokens listos para la validación gramatical:

TK_TYPE: 'int'
TK_ID: 'contador'
TK_ASSIGN: '='
TK_NUM: 10

Actividad 1: Autómatas de Pila vs. Autómatas Finitos

¿Por qué necesitamos una pila (LIFO) para superar los límites de los lenguajes regulares?

Definición Formal del Autómata de Pila

Un autómata de pila M se define rigurosamente como una tupla de 7 componentes:

M = (Q, Σ, Γ, δ, q₀, Z₀, F)
  • Q: Conjunto finito de estados. | Σ: Alfabeto de entrada.
  • Γ: Alfabeto de la pila LIFO. | Z0: Símbolo inicial de pila.
  • δ: Función de transición (δ: Q × (Σ ∪ {ε}) × Γ → ℧(Q × Γ*)).
Supremacía sobre el AFD (Jerarquía de Chomsky)
  • AFD / AFND (Tipo 3 - Regulares): Memoria finita fija. Son perfectos para el Lexer, pero no pueden contar anidamientos infinitos.
  • Autómata de Pila (Tipo 2 - Libres de Contexto): Puede emparejar paréntesis y verificar bloques de llaves apilando y desapilando.
Ejemplo Clave: L = { an bn | n ≥ 1 }

Apila 'A' por cada 'a' y desapila por cada 'b', garantizando emparejamiento exacto.

Actividad 2: Lexer para Archivos Dockerfile en Python

Construcción manual utilizando Expresiones Regulares del módulo re y generadores iterativos.

Arquitectura y Expresiones Regulares

El analizador (dockerfile_lexer.py) no requiere Docker instalado. Define una lista ordenada de tuplas con regex para evitar falsas coincidencias:

DOCKER_TOKENS = [
  ('COMMENT', r'^\s*#.*'),
  ('DIRECTIVE', r'\b(?:FROM|RUN|CMD|COPY|ENV|EXPOSE)\b'),
  ('FLAG', r'--[a-zA-Z0-9_-]+(?:=[a-zA-Z0-9_./:-]+)?'),
  ('VARIABLE', r'\$[a-zA-Z_]\w*|\$\{[^}]+\}'),
  ('PORT', r'\b\d{1,5}/(?:tcp|udp)\b'),
  ('MISMATCH', r'.') # Regla de captura de errores
]
Eficiencia con re.finditer y Geometría

En lugar de dividir la cadena lentamente con .split(), combinamos todos los patrones con alternancia y nombres de grupo: (?P<DIRECTIVE>...)|(?P<FLAG>...).

  • Pasada única (O(n)): Escanea el archivo de principio a fin de forma continua.
  • Control de Línea y Columna: Al coincidir con NEWLINE, incrementa line_num y reinicia el desplazamiento line_start. Si coincide con MISMATCH, calcula la columna exacta y dispara un SyntaxError.

Actividad 3: Metacompilador Flex (Fast Lexical Generator)

Automatización industrial: generar un autómata determinístico en C (lex.yy.c) desde reglas .l.

Estructura en 3 Secciones de un Archivo .l
%{
  /* 1. SECCIÓN DE DEFINICIONES EN C */
  #include <stdio.h>
  int line_num = 1, col_num = 1;
%}
%option noyywrap yylineno
DIGITO [0-9]
%%
/* 2. SECCIÓN DE REGLAS Y ACCIONES */
"fn"      { printf("TK_FN: %s\n", yytext); }
{DIGITO}+ { printf("TK_INT: %s\n", yytext); }
.         { printf("ERROR_LEXICO: %s\n", yytext); }
%%
/* 3. CÓDIGO C DE USUARIO (MAIN / YYLEX) */
int main() { yylex(); return 0; }
Elementos Internos de Flex
  • yytext: Puntero a la cadena exacta que acaba de coincidir con el patrón.
  • yyleng: Longitud en caracteres del lexema capturado en yytext.
  • yylex(): Función autogenerada por Flex que inicia el bucle de lectura sobre yyin.
Regla del Longest Match

Si una cadena puede coincidir con dos reglas, Flex elige la coincidencia más larga o, a igual longitud, la que fue escrita primero en el archivo.

Actividad 4: Flex en el Área de Seguridad Informática

¿Por qué los cortafuegos ultrarrápidos e IDS/IPS mundiales utilizan analizadores léxicos en C?

1. IDS/IPS (Snort & Suricata)

Inspeccionan tráfico a 100 Gbps. El motor tokeniza cabeceras IP/TCP y opciones (content:"|00 01|"; sid:10001) a velocidad lineal O(n) sin causar latencia de red.

Detección de Intrusos
2. Reglas YARA (Malware)

YARA (libyara) es el estándar forense. Utiliza internamente Flex y Bison para compilar las reglas del analista (rule, meta:, strings:, condition:) en memoria.

Adjunto: yara_lexer_demo.l
3. WAF (ModSecurity)

Tokeniza peticiones HTTP, cabeceras y parámetros para detectar gramáticas maliciosas de inyección SQL (SQLi) o Cross-Site Scripting (XSS) al vuelo.

Síntesis académica del Tema 4: Desde la teoría de máquinas abstractas al software ejecutable.

Conclusiones Clave del Equipo
  • Purificación del Código: El Lexer simplifica el trabajo al Parser al filtrar comentarios (SKIP) y agrupar bytes en lexemas válidos.
  • AFD vs. PDA: El autómata finito es insuperable para tokenizar a velocidad O(n), mientras que la pila del PDA es imprescindible para la sintaxis.
  • Manual vs. Metacompilador: El desarrollo en Python da personalización en mensajes de error; Flex aporta estandarización y rendimiento en C.
